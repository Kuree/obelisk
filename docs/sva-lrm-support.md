# SystemVerilog assertion conformance

This document tracks Obelisk against the assertion facilities in IEEE Std
1800-2023.  It deliberately distinguishes three levels of support:

- **Executable** means the construct has LRM-oriented simulation semantics in
  both the native and bytecode tiers and has differential tests.
- **Semantic IR** means the elaborated construct and its resolved metadata are
  preserved without claiming that it can be simulated yet.
- **Rejected** means lowering emits a targeted diagnostic.  Rejection is
  preferred to an approximation with different scheduling, sampling, vacuity,
  or endpoint semantics.

Obelisk does **not** currently implement the full SVA language. Passing UVM or
the pinned sv-tests corpus demonstrates the executable subset those suites
exercise; it is not a claim of complete IEEE 1800 assertion conformance.

The active normative reference is IEEE Std 1800-2023, principally the
assertions and checker chapters and the assertion-related system tasks and
functions.  The standard is available through the IEEE GET program:
<https://standards.ieee.org/ieee/1800/7743/>.

## Conformance matrix

| LRM surface | Current level | Implemented boundary | Work required for full conformance |
| --- | --- | --- | --- |
| Immediate `assert`, `assume`, and `cover` | Executable subset | Four-state truth conversion, explicit action blocks, and default `assert`/`assume` failure diagnostics lower to ordinary control flow. | Complete immediate-cover evaluation/success accounting and all assertion-control interactions. |
| Deferred immediate `#0` and `final` | Executable subset | The expression is evaluated at encounter. Per-process/site tickets implement last-report-wins. `#0` matures in Observed and actions run in Reactive; `final` matures in read-only Postponed. Value inputs are captured while output/ref arguments remain references. Pending tickets are flushed on process resumption and outermost process-scope disable. Disabling a labeled assertion cancels only its matching tickets in the LRM-defined logical-process scope. | Complete every subroutine argument-expression capture case and the remaining assertion-control system tasks. |
| Concurrent directive kinds | Executable subset | Bounded `assert property`, `assume property`, `cover property`, `cover sequence`, and simulation-silent `restrict property` compile to generated monitors. Procedural `expect` supports one-shot fixed sequences without locals, implication, disable conditions, or match items; its caller blocks on a private completion event and resumes in Reactive for the action block. | Add the remaining temporal forms, extend `expect` to the full property surface, and complete directive counters and controls. |
| Clock resolution and sampling regions | Executable subset | Resolved explicit or default direct edge clocks are retained, including an executable `iff` qualifier whose false/X/Z value suppresses the clock tick and starts no property attempt. Concurrent predicates and sampled-value functions read the canonical once-per-slot Preponed snapshot; monitor bookkeeping runs in Observed. The leading-`##1` multi-clock form may hand off between nonempty boolean stages through fixed `##1`; each source-clock start creates an independent attempt whose next stage uses the nearest strictly subsequent destination-clock tick. | Add an immediate first term (`a ##1 ...`), `##0` multi-clock handoff, composition across maximal clocked subsequences, virtual-interface clocking-event `iff`, sequence/property clock arguments, global clocking, and all legal inferred-clock contexts. |
| Sampled-value functions | Executable subset | `$sampled`, `$past`, `$rose`, `$fell`, `$stable`, and `$changed` work on statically addressable packed storage. `$past` supports constant positive depth and a statically addressable gate, using bounded per-logical-process history. Concurrent predicates may select a direct alternate edge clock with an optional direct `iff`; Postponed history updates preserve strictly prior-clock semantics. The compiler coalesces referenced canonical bit ranges so Preponed capture copies only sampled state. | Add simultaneous `$past` gate plus explicit-clock `iff`, automatic/computed operands, full clock-context validation, and the remaining global sampled-value functions. |
| Boolean sequence terms | Executable subset | Four-state sampled terms are converted to assertion truth in generated SSA. | Support arbitrary legal sequence expressions, formal arguments, local variables, and match items. |
| Cycle delay `##` | Executable subset | Fixed nonnegative `##N` and small bounded `##[M:N]` ranges are compiled AOT with a total horizon of at most 63 samples. Branching expansion is capped at 256 exact traces. One final `##[M:$]` with `M <= 63`, a deterministic bounded prefix, and one Boolean terminal uses a bounded warm-up bitset plus one merged eligible-token count. Ordinary sequence properties take the first match, while `cover sequence` preserves every successful endpoint. A one-cycle Boolean antecedent may feed a leading `##[M:$]` Boolean consequent through implication or followed-by; nonoverlapping forms retain the one-clock handoff explicitly. Bare assert/assume sequences complete weakly and explicit `strong` completes pending tokens as failures at end of simulation. Static `disable iff` clears the complete aggregate state and invalidates queued and finite-end reports. An outer abort completes and clears every aggregate warm-up and eligible attempt through the shared counted dispatcher. | Compose unbounded delay with multi-cycle/branching antecedents, explicit consequent prefixes, locals and branching operators; add larger endpoint sets without trace expansion and dynamic delay extensions if supported by policy. |
| Repetition | Executable subset | Fixed and finite consecutive `[*N]` / `[*M:N]` repetition within the 63-sample horizon and 256-trace cap is compiled AOT. Count zero is represented as an exact empty trace and the IEEE positive-delay concatenation rewrites eliminate it, including common forms such as `b ##1 a[*0:1] ##2 c`; a sequence promoted directly to a property still may not admit an empty match. Common positive finite or unbounded-upper `[->M:N/$]` and `[=M:N/$]` forms, plus positive `[*M:$]`, are executable over one Boolean term alone or with a deterministic bounded prefix and one `##1` Boolean continuation. Unbounded occurrence counts saturate at M because every larger count has identical future behavior. A fixed-size aggregate token DFA therefore uses at most O(M) integer state rather than one runtime process per live attempt; action multiplicity and weak/strong end-of-simulation completion use counted Reactive dispatch. Static `disable iff` resets every DFA cell atomically and epoch-invalidates already queued completions. An outer synchronous or static asynchronous abort sums and clears every aggregate token cell before dispatching the selected completion once per live attempt. | Add zero-minimum unbounded repetition, the remaining empty/degenerate composition rules, general continuations/composition, locals and match items, `first_match`/implication integration, and cover-sequence per-endpoint accounting. |
| Sequence composition | Executable subset | Bounded `and`, `or`, `intersect`, `throughout`, and `within` compile to at most 256 exact traces for plain concurrent directives without locals, implication, `disable iff`, or `expect`. Bounded `first_match` priority groups may be nested or concatenated; every direct or expanded-invocation scope independently selects its earliest successful endpoint and cancels only that scope's later alternatives. Branching `cover sequence` retains every live alternative and schedules its action once per successful endpoint. Equivalent direct clocks flow through named sequence expansion. | Replace trace expansion with compact thread merging, add persistent cover counters, match-item/local flow, and operator-specific empty-match rules. |
| Property implication and followed-by | Executable subset | `|->`, `|=>`, `#-#`, and `#=#` work for bounded antecedent and deterministic consequent sequences within a combined 63-sample state horizon. Small branching antecedents, including Boolean `or` and bounded ranged endpoints, retain every successful endpoint. One compact consequent channel per exact antecedent trace preserves simultaneous same-cycle obligations without runtime thread spawning, while one matched-history bitset delays vacuity only until all alternatives for that property attempt are exhausted. The common one-cycle-antecedent form also composes with a leading `##[M:$]` Boolean consequent using aggregate warm-up/eligible state. Failed implication antecedents produce vacuous assertion success but never a cover hit; failed followed-by antecedents report failure instead. | Add branching consequents, explicit persistent-consequent prefixes, vacuity control/accounting, assertion-local flow through branching/multi-cycle antecedents, and composition with all property operators. |
| Other property operators | Executable subset | Deterministic one-cycle boolean operands support property `not`, `iff`, and `implies`. Conditional `if`/`else` and ordinary case-equality `case` properties support bounded branches. Missing else/default branches are retained as vacuous successes and do not create cover-property hits; case items preserve source priority and four-state case equality. Fixed `nexttime` / `s_nexttime` and explicitly finite-range `always` / `s_always` / `eventually` / `s_eventually` compile to bounded traces. Common unbounded weak `always` and strong `s_eventually`, including `[M:$]`, use one eligible-attempt count plus an optional saturating warm-up count. They close every surviving attempt with the IEEE weak-success or strong-failure result at end of simulation without spawning one monitor per attempt. Common Boolean `until`, `s_until`, `until_with`, and `s_until_with` similarly use one aggregate live-attempt counter and canonical minimal transition guards; strong-until failures and weak-until vacuous successes close outstanding attempts at end of simulation. Static `disable iff` clears all persistent counters and suppresses their stale Reactive and finite-end completions. Counted Reactive dispatch preserves per-attempt action multiplicity. Equivalent same-endpoint bounded Boolean traces are minimized by compiler-side Z3 before monitor SSA is built; generated simulation has no solver dependency. | Generalize temporal operand composition, including persistent and branching forms, vacuity, and the precise attempt/thread semantics of the remaining temporal operators. |
| `strong` / `weak` | Executable subset | One outermost qualification around a deterministic bounded property uses the existing live-attempt bitset. Final `##[M:$]` delays and persistent repetition use their aggregate count/bitset state. Intrinsically strong/weak persistent until also closes its aggregate live-attempt count. At end of simulation a compact final-phase coordinator completes every outstanding attempt: strong semantics dispatch failure and weak semantics dispatch vacuous success. The callbacks execute as final-phase Reactive actors; weak completion does not create a cover-property hit. One-cycle properties allocate no final state. | Compose outer strong/weak qualification with branching alternatives, implication/followed-by beyond the common persistent-delay slice, persistent until, multiple `first_match` scopes, `expect`, and cover-sequence per-match accounting, then integrate full vacuity controls and counters. |
| `disable iff` | Executable subset | Explicit and resolved default conditions over static design state are unsampled asynchronous observers. A true condition clears live bounded attempts and the complete aggregate state of common final `##[M:$]`, unbounded repetition, unbounded temporal unary, and persistent-until monitors. It prevents new attempts while true and epoch-invalidates results already queued for Reactive action or finite-end completion in the same slot. X/Z is not true. | Support automatic operands and compose cancellation with branching/`first_match`, abort operators, assertion controls, and per-attempt local state. |
| `accept_on`, `reject_on`, `sync_accept_on`, `sync_reject_on` | Executable subset | All four operators wrap a deterministic bounded property or one of the common aggregate persistent forms: final `##[M:$]`, unbounded temporal unary, persistent until, and positive unbounded-upper repetition. A synchronous abort uses the clock's Preponed sample. An asynchronous abort uses a static computed observer and completes live attempts in Reactive when its unsampled condition becomes true; the clocked path also gives an already-true condition priority over the attempt starting on that clock. Persistent monitors share one zero-time counted dispatcher that sums and clears every live aggregate cell before scheduling the selected result once per attempt. Every affected attempt completes exactly once, accepted results are vacuous and do not create cover hits, and rejected results schedule failure. | Compose aborts with automatic operands, locals, branching properties, implication/followed-by, `disable iff`, `first_match`, `expect`, and cover-sequence per-match accounting, then integrate vacuous controls/counters. |
| Sequence/property declarations and calls | Executable subset | Nonrecursive invocations with a frontend-expanded body execute through the same bounded and selected persistent compilers as inline properties. Parameter actuals and defaults are already substituted in that body; retained source actual/default children are semantic inventory and are deliberately not evaluated a second time. Symbol references, formal metadata, local metadata, default clocks/default disables, and recursive placeholders remain preserved. | Add recursive-property execution and the remaining formal directions/types, clock formals, local/thread flow, and declaration bodies whose frontend representation cannot supply an expanded invocation. Preserve a standalone declaration body when the frontend API exposes one for a declaration with required formals. |
| Local variables and sequence match items | Executable subset | Fixed packed locals have per-attempt storage and ordered blocking assignments. One value-only, receiver-free subroutine match call per endpoint is detached into Reactive with its local arguments captured at the match point. | Add arbitrary endpoint/thread flow, multiple ordered calls, ref/output arguments, implicit receivers, and nonlocal argument expressions. |
| Assertion action scheduling | Executable subset | Deferred immediate reports/actions use the LRM regions. Bounded concurrent monitors evaluate in Observed and dispatch explicit pass/fail actions or default `assert`/`assume` failures as detached Reactive callbacks. Arbitrary same-slot callback fanout is scheduler-owned, and asynchronous `disable iff` invalidates queued callbacks before their action executes. Forced native AOT remains a hybrid plan for these cold callbacks and cancellation observers; it does not relabel them as fully static work. | Add action controls, reporting/counters, `expect`, and action lifetime/capture for the remaining temporal forms. |
| Assertion control system tasks | Executable subset | Stable assertion paths/target IDs are retained for labeled immediate assertions. `$asserton`, `$assertoff`, `$assertkill`, and `$assertcontrol` actions 3/4/5 support constant levels, assertion-type and directive masks, plus global, module-instance, and exact-assertion selection. Off prevents new encounters while preserving queued deferred reports; Kill additionally cancels matching tickets. Designs without a selected control target emit no enabled-state lookup. | Add pass/fail and vacuous/nonvacuous controls, counters, dynamic/procedural selectors, concurrent-attempt control, and the remaining control actions. |
| Attempt, success, failure and vacuity accounting | Rejected except observable immediate failures | No incomplete counters are exposed. | Add counters and query/control behavior for immediate and concurrent assertions, including vacuous success and disabled/killed attempts. |
| Checker declarations and instances | Semantic IR | Checker declaration ports; static and procedural instance identities; resolved formal/actual connection metadata; instance-body declaration/parent identity, nesting and context; and procedural checker-statement identities are preserved with verifiers. An elaborated instance body retains its cloned ports, default clock/default disable, properties, assertions, procedures, and expressions. | Execute checker procedures/assertions, infer all checker clocks, implement free-variable and hierarchy behavior, and preserve a standalone uninstantiated body if the frontend exposes one; currently Slang exposes member bodies only through an elaborated `CheckerInstanceBodySymbol`. |
| Assertion VPI/API | Rejected | No partial assertion object model is exposed. | Add assertion/attempt objects, callbacks, reason/status data, controls, and stable hierarchy after core simulation semantics are complete. |

## Implementation order

The remaining work has semantic dependencies and should not be implemented as
independent syntax cases:

1. Finish the bounded monitor surface: empty-match rules, branching
   match-item flow, and branching consequents.
2. Compose the compact live-attempt counters and final-phase closure already
   used by unbounded weak `always`, strong `s_eventually`, final `##[M:$]`
   delays, and positive unbounded-upper repetition with persistent/branching
   property operators.
3. Generalize clock inference and maximal clocked subsequences, then compose
   abort operators, automatic locals, and ordered Reactive match actions with
   that attempt model.
4. Build complete attempt/success/failure/vacuity accounting and assertion
   controls on the stable core semantics. Checker execution and assertion VPI
   follow because both expose those identities and counters publicly.

This ordering keeps bounded assertions fast while avoiding temporary
implementations whose vacuity, endpoint, or event-region behavior would later
have to change.

## Runtime architecture

Temporal execution is compiled ahead of time into ordinary verified simulation
SSA and compact monitor state.  The runtime performs scheduling, Preponed
snapshot reads, bounded history access, and report dispatch; it does not parse
properties or run a temporal interpreter.

Z3 is an optional **compiler-only** dependency used by constrained-random
planning and by bounded-SVA trace minimization.  SVA lowering uses it only to
remove equivalent generated Boolean work; a direct conservative monitor is
emitted when `OBELISK_ENABLE_Z3=OFF` or a proof is unavailable.
`libobelisk_rt`, generated native
executables, bytecode images, and target runtime archives must never contain or
link Z3 code.  Solver failure or an unavailable proof must only select a
conservative generated monitor, never change assertion semantics.

## Completion criteria

An item moves to **Executable** only when tests cover its syntax, four-state
sampling, overlapping attempts, vacuity/end-of-simulation behavior where
applicable, cancellation and assertion controls, region ordering, and native /
bytecode behavior at both O0 and O3.  Full SVA support additionally requires a
green `OBELISK_ENABLE_Z3=OFF` build and regression suite; compiler-side solver
tests are supplementary rather than a correctness dependency.
