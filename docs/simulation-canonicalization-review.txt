Simulation operation canonicalization review — 2026-10-07
Baseline: main 5004d969; IEEE 1800-2023 from build/lrm-2023.txt.

Scope and method
Reviewed the 367 SimulationOps.td declarations by operation family, including
102 declarations explicitly carrying Pure, their folders/patterns, verifiers,
and the standard/runtime lowerings relevant to the new rules. This is an
operation-family audit, not a claim to enumerate every equivalent expression.
The op contracts already resolve SystemVerilog width and signedness. Rewrites
must preserve those contracts, including X/Z encoding and diagnostic effects.

Arithmetic — 11.4.3, 11.6, 11.8
Existing: constant arithmetic, fixed-width overflow, signed MIN/-1, divide and
remainder by zero, modular power; known add/sub/mul exported to arith.
Added: a single constant operand containing X/Z determines the entire result;
constant zero divisor determines X even with a dynamic dividend. Same rule
for an unknown power operand. Associate adjacent constants for add/mul only
when the inner operation has one use, at the same resolved width.
Known unary negate/bitwise-not/logical-not now become ordinary integer ops.
Do not remove x+0, x*0, x**0, x/x or x%x without the required knownness/nonzero
proof. Signed negative powers remain the responsibility of semantic lowering.
No division reassociation and no integer-to-float host arithmetic shortcuts.

Bitwise/logical/reduction — 11.4.7-9
Existing: complete constant truth tables, AND-zero/OR-ones controlling values,
known bitwise operations exported to arith.
Added: adjacent bitwise constants combine under the associative four-state
truth tables; the remaining operation is retained to normalize Z to X.
Logical identities and self-operations become reduction OR, not raw operands.
Known logical operands and AND/NAND/OR/NOR reductions expose arith operations.
Reducing repeated words uses one word for AND/NAND/OR/NOR, and for XOR/XNOR
only for odd replication counts. Even replication does not make unknown parity
zero. Constant evaluation is shared with the dialect folder, not reimplemented
in each pattern. Short-circuit side effects have already been represented in
the CFG; rewriting a pure value does not delete its effectful producers.

Comparisons/mux — 11.4.4-6, 11.4.11, Table 11-20
Existing: exact case equality, asymmetric wildcard semantics, known mismatch
for logical equality, signed/unsigned comparisons, ambiguous mux bit merging.
Added: wildcard self-comparison; exact per-bit difference-mask constant/self
folds and two-state XOR; known-condition mux becomes arith.select. Identical
arms collapse for a known two-state arm, not for arbitrary logic.
Added standard 1:N arith.select conversion so selection preserves both planes
and a selected Z. It uses OpConversionPattern and the existing type converter.
The existing sparse known-bit and demanded-bit analyses and state-domain
analysis carry facts through the select, so canonicalization retains precision.
Unknown-condition equal Z arms must still become X. A two-state destination
does not establish that the input expression was two-state.

Concatenation, resizing and selection — 11.4.10, 11.4.12, 11.5, 11.6, 11.8
Existing: nested concat flattening, repetition coalescing, adjacent slice
merging, resize-chain composition, extract-of-insert, overwrite removal,
constant dynamic indices, negative/partial/OOB/XZ selection semantics.
Added: strip an explicit from_bits on a shift amount, retaining its full width.
Do not map shifts straight to LLVM/arith shifts unless out-of-range amounts
are guarded. Do not narrow arbitrary-width indices before checking bounds.
General demanded-width reduction belongs in the existing sparse backward
DemandedBitAnalysis; partial knownness belongs in sparse LogicBitAnalysis.
Local folders must not grow an independent recursive whole-function analysis.

Arrays, structs, unions, bitstreams — 7.2-7.4, 10.9, 6.24.3
Existing: construct/extract, inverse reconstruction, overwrite insertion,
constant array access, fixed default values, packed flatten/unflatten inverses,
bounded small bitstream exports, exact union construction/extraction.
Added: extract from splat, repeated scalar array construct to splat, insert
into a single-use construct. Exclude managed/float splat elements and structs
from array-splat formation; avoid the existing singleton inverse pattern.
Dense memory snapshot forwarding now handles packed slices and aggregate
fields through exact dynamic parents. It keeps stores/publications and drops
facts on aliasing writes, calls, suspension, joins with unequal values and
reference rebinding. Tagged/unpacked union field reconstruction is rejected.
Bitstream roundtrips require exact plan, width, padding, tag, and X/Z proofs;
unpacked ABI storage width is not the language bitstream width.

Bit system functions — 20.8-20.9
Existing: constant countbits/clog2.
Added: integer constant countbits and all-four-state-control count folding for
packed inputs. Duplicate controls select a set; do not count them twice.
No all-controls shortcut using unpacked storage span, because it has padding.

Strings — 6.16, especially 6.16.3 and 6.16.7-8; literal sizing 5.9
Existing: literal length/lexical comparisons and exact packed conversion.
Added: self-comparison, literal getc (including invalid indices and high bytes),
and literal ordinary packed conversion (right justification, zero extension,
truncation and non-byte widths).
Dynamic parsing, atoi/atof, plusarg parsing need a shared parser contract;
copying the runtime's parser into a canonicalizer would create two semantic
implementations. Allocating string operations retain their heap effects.

Handles, references, class/interface operations — 6.14, 6.17, 7, 8, 9.7, 25.9
Existing: typed null constants, canonical reference view composition, mem2reg
interfaces, fixed array/slice reference specialization.
Added: reflexive chandle/process/event/virtual-interface identity equality,
managed null test, same-type virtual-interface cast. Different handles remain
unknown; different modport views remain explicit.
Class checked casts, class field refs, boxed casts, interface binding and
closed-world dispatch retention require type/symbol/lifetime contracts; do not
turn their Pure marker into permission to drop validation or retained symbols.
Context projections are already CSE-able; they are runtime identities, not
compile-time addresses. Managed container reads depend on live heap state.

Time, real, random — 3.14, 6.12, 11.4, 18, 20.15
Existing: checked constant time addition and zero identities. Other time/real
ops lower into arithmetic with explicit scaling, quantization and rounding.
Keep overflow/negative-delay diagnostics, floating NaN/Inf/signed-zero behavior,
real-to-integer rounding and target representation. Random draw/state operations
must preserve seed evolution and diagnostics; not ordinary algebraic identities.
Template random operands need their binding context, not an invented constant.

Effects and structural operations — 4.4-4.7, 9, 10.4, 12.5.3, 13, 14, 16, 21
Calls, storage/net/driver publications, force/release, NBA, delays, event waits,
process controls, sampled/deferred assertions, clocking, timing checks,
coverage, monitors, dumps, files/DPI and external access are not pure op folds.
Preserve event regions, sequential statement order, observer-visible writes and
invalid-access diagnostics. Removal needs the established effect/alias/dataflow
analyses. Standard canonicalization/CSE now runs after interleaved kernel
materialization; keep the activation wait block and existing fusion policy.
Unique-case constants prove disjointness by exact equal-width (value,unknown)
keys across ITEMS. Keep dynamic labels, wildcard cases, conversions, duplicate
cross-item labels, and unique no-match diagnostics on their required paths.
The kernel forwarding path is admitted only by CombinationalFusionAnalysis,
which globally rejects DPI/force/release/process-control hazards, and with VPI
off. SimplifyBodies independently retains its VPI/force/release guard.

Validation and remaining work
New MLIR regressions cover positive and refusal cases, wide/narrow widths,
fixed points, retained side effects, tagged-member access, alias invalidation,
CFG joins and external writes across suspension. The exhaustive native/Wasm
oracle compares canonical lowering and ordinary lowering against separate LRM
truth tables for all 256 four-state four-bit words and 65,536 operand pairs.
RSD measurements, complete test results and accepted commits are recorded in
tmp/rsd-insn-gap/profiled-ports/ACCEPTANCE.txt.
The sparse select transfer regression additionally checks known low slices,
retained unknown high slices, and two-state versus four-state specialization.

The larger remaining opportunity is measured dataflow precision and lowering
cost in hot code, not an ever-growing catalog of peepholes. Existing sparse
LogicBitAnalysis/DemandedBitAnalysis and state-domain proofs should be extended
where profiles show a lost fact. Dispatch, NBA and repeated publication costs
need their own effect-aware transformations and direct RSD measurements.
