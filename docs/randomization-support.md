# Randomization support

This matrix separates the executable unconstrained random-number and stream
foundation from the remaining constrained-randomization work. A row is
“executable” only when it follows the same typed Simulation IR through native
and whole-design bytecode execution.

| Feature | Current boundary |
| --- | --- |
| Generator | Executable PCG-XSH-RR with explicit `{state, increment}` state and the existing `--seed=<u64>` option. The bounded draw uses rejection debiasing. |
| Process streams | Executable. Root processes split from the seeded context stream, and forked processes split the active parent stream in lexical spawn order. Bytecode tasks retain their stream while dequeued from the scheduler. |
| Object streams | Executable for the constrained-randomization slice. Every root class contains two hidden, inline, GC-invisible `i64` fields. Construction initializes them before `new`; class copy reseeds the copy; `randomize()` advances this object-local PCG state in native and bytecode execution. |
| `$urandom` | Executable with zero arguments and with the optional seed argument. |
| `$urandom_range` | Executable with one or two arguments, including reversed bounds, with an unbiased inclusive range. |
| `$random` | Executable with zero arguments. The optional seed form reseeds the active stream and writes the generated value back to the seed variable. |
| `$srandom` | Executable with one argument; it reseeds the active process stream without drawing a value. |
| Stream snapshot API | The runtime C ABI supports exact get/set of both PCG words and pure state-local stepping/bounded draws. Object `get_randstate` / `set_randstate` source methods are pending their string encoding. |
| Constraint blocks and `randomize()` | Executable for non-static packed integral, enum, packed aggregate, and frontend-admitted packed tagged-union `rand` properties and for `randc` properties up to the boundary below. Enum enumerators and canonical tagged-union arm encodings form exact semantic domains rather than exposing unused packed encodings; packed arrays and structs recursively compose nested enum domains. A base- or interface-class-typed handle is specialized at compile time for every compatible concrete class and selects the most-derived plan with generated in-process type tests; the receiver is evaluated once, and a null or otherwise unmatched handle returns zero without touching object state. `randomize(null)` uses the same dynamic plan selection as `randomize()`, invokes `pre_randomize`, checks the current property values against the live constraint-mode mask, and invokes `post_randomize` only on success; it performs no random draws, property writes, or hidden-state changes. Total, side-effect-free hard expression constraints, up to 64 soft expression preferences including implication- and conditional-guarded preferences, `inside` ranges, implication, conditional constraints, uniqueness, inheritance, package/design captures, inline `with` constraints, and side-effect-free user constraint functions compile to pointer-free SSA. Packed concatenation and known-positive constant replication are preserved in compile-time definitions and in residual programs; replication uses a fixed-width geometric placement multiplier rather than expanding one runtime operation per repetition. Admitted functions have packed input or const-ref arguments and define their result with one expression return or blocking return-variable assignment; nested calls are expanded recursively and virtual calls on the randomized receiver resolve against the selected concrete-class plan. Rand packed value paths passed as function arguments remain solver variables and create bit-range-precise LRM implicit solve-order edges, while rand properties read only inside the function body are captured at their pre-solve values. Dynamic candidate-dependent packed selections in those paths remain unsupported. Each constraint tree is separated into its hard projection and guarded soft predicates. Later class declarations, derived-class constraints, and inline constraints receive progressively higher soft priority. For capture-free formulas, Z3 selects the lexicographically best satisfiable priority set and proves exact structural domains, definitions, or tables for generated code. Capture-dependent or dynamically disabled preferences remain on the complete residual traversal, which selects the best enabled priority set before dropping lower-priority preferences. Fixed-width shifts are total, including oversized amounts. Division and modulo are accepted with a statically known nonzero divisor. Integral power accepts an unsigned exponent or a statically known nonnegative signed exponent. These operators participate in Z3 proofs and compile-time proposal definitions; the versioned pointer-free runtime program implements the same operations for residual fallback. The object-local PCG draw chooses the starting assignment. Generated code checks up to 64 cyclic semantic candidates, then invokes the fallback with a deterministic attempt budget of up to 2^20 semantic assignments. Property and hidden `randc` cycle-state writes occur only on the success edge, so failed solves commit nothing. Constraint functions with procedural control flow or an explicit receiver other than the randomized object, system-function calls in constraints, dynamic-zero division, and signed dynamic or negative integral exponents remain unsupported. Object property argument lists and `std::randomize` receive explicit unsupported-boundary diagnostics rather than being silently miscompiled. |
| `rand_mode` / `constraint_mode` | Class-wide and property-specific `rand_mode` setters and queries are executable through a zero-initialized disabled-property mask. Disabled properties retain their current values, participate in constraints as state variables, consume no search-domain bits, and are not written on success. Class-wide `constraint_mode(on_off)` and named-block setters and queries are executable through a separate disabled-block mask for up to 64 effective inherited constraint blocks. Overrides retain the base block's stable bit; `constraint ... extends` declarations append under that same bit. The all-enabled constraint path retains its Z3-planned sampler. Any disabled block bypasses plan-specific narrowing and extra draws, uses the generated live-mask checker, and passes both property and constraint masks to the deterministic residual solver. Inline constraints remain unmaskable. If all random properties are disabled, `randomize()` checks current values against the enabled hard constraints without advancing the object stream or writing properties. |
| `solve before` | Direct rand-property DAGs are executable. The compiler validates self edges and cycles, reorients pure alias classes toward the earliest ordered member, and emits conditional sampling directly as MLIR when Z3 can provide complete capture-free global/component tables (up to 4096 representation bits and 16 solutions per table) or verify an exact structural/capture-assisted plan whose transitive dependencies follow the solve order. Capture-free soft preferences participate in that exact plan after compile-time priority selection. Independent components stay factored, avoiding a potentially large Cartesian-product table. The residual program retains constraint-block-aware ordering edges for reverse definitions, non-structural correlations, unresolved soft preferences, and property/constraint mode changes. Its bounded runtime path exhaustively finds the best enabled soft solution set, then uses unbiased bounded draws from the object-local PCG stream to select each active topological layer conditionally; disabled properties are fixed and disabling a constraint block also removes its ordering edges. A compile-time diagnostic rejects an all-enabled residual ordered plan whose semantic domain exceeds 2^20 assignments instead of silently emitting a path that cannot preserve the distribution. Dynamically selected subsets that retain an active ordering edge also fail deterministically when their mutable semantic domain exceeds that bound; subsets with every ordering edge disabled use the ordinary bounded residual search. |
| `dist` | Executable for a direct packed integral or enum `rand` property with compile-time two-state singleton/range endpoints, including unary signed constants. Both `:=` per-value weights and `:/` per-range weights, including a default weight, are normalized exactly with checked 64-bit integer arithmetic. State-dependent packed integral weights are evaluated once at driver entry. Generated MLIR performs unbiased weighted range selection for ordinary packed domains. Finite semantic domains use compiler-counted legal values and the exact residual path, so sparse enum encodings do not distort `:/` normalization; this path currently requires at most 2^20 aggregate semantic assignments. The same normalized per-value table is serialized for constraint/property-mode fallback. The fallback attaches mass once to each distinct tuple of distributed target values, so unrelated companion-solution multiplicity cannot skew the declared distribution. Signed target domains use sign-bit-biased coordinates. Negative dynamic weights, zero total weight, or arithmetic overflow make `randomize()` fail rather than introduce bias. Soft `dist`, `dist` combined with `solve before`, `dist` on `randc`, multiple active distributions for one property, candidate-dependent weights, dynamic endpoints, and normalization or range mass that exceeds 64 bits are diagnosed explicitly. |
| `randc` | Executable for packed semantic domains containing at most 2^32 values within a packed representation no wider than 32 bits. Sparse enum and tagged-domain values are addressed by dense semantic indices, so unused encodings are skipped without bias. Each property has hidden GC-invisible key and position fields. A deterministic keyed four-round Feistel permutation produces every semantic index exactly once per cycle in O(1) state; wrapping explicitly draws a new key from the object-local PCG stream. An enabled `randc` value advances before ordinary `rand` solving and is held fixed while its constraints are solved. Its field, key, and position are committed together only after a successful solve. A disabled property retains both its value and cycle state. The pure Simulation op lowers to a direct runtime API call in native code and to the corresponding intrinsic in whole-design bytecode; runtime GoogleTests exhaustively prove bijectivity through width 16 and exercise the bytecode intrinsic. Wider representations or semantic domains larger than 2^32 are diagnosed. |
| `pre_randomize` / `post_randomize` | Executable with virtual override semantics through the same compile-time-specialized dynamic-class plan as `randomize()`. The effective `pre_randomize` runs after receiver selection but before mode, constraint, property, or stream state is read. The effective `post_randomize` runs after all successful property and `randc` state commits, including a successful current-value check when every property is disabled, and is skipped on failure and null receivers. Inherited hooks receive a receiver cast to their declaring class. Package and design captures used by either hook are propagated through the generated call plan. |
| Compiler Z3 planning | A pinned Z3 4.13.4 static library is built from source for the compiler only. Residual programs are decoded into a temporary MLIR SMT bit-vector formula, then an in-process shim executes that formula through the Z3 API; no solver subprocess or SMT-LIB round trip is used. Z3 diagnoses constraints that are unsatisfiable for every runtime capture value and computes conservative per-property domains under a deterministic resource limit. Contiguous domains up to 64 bits are folded without modulo bias into the generated tier-0 proposal: power-of-two cardinalities use random low bits, while arbitrary cardinalities use generated 64-bit rejection sampling and overflow-safe cyclic retry traversal. Wider variables skip width-linear min/max discovery and instead use bounded solution enumeration when sparse. Direct signed and unsigned capture bounds up to 64 bits, including side-effect-free capture expressions evaluated once at driver entry, such as `x <= limit`, `x >= limit`, or their strict forms, become parameterized MLIR samplers: captures are masked once, signed endpoints are mapped to sign-bit-biased unsigned coordinates, strict endpoints are normalized with overflow guards, compatible lower and upper bounds and compile-time envelopes are intersected, and the runtime cardinality is sampled with unbiased 64-bit rejection. A zero cardinality represents the full 2^64-element domain and selects the original random draw while generated modulo operations use a nonzero safe divisor. An empty runtime intersection fails before modulo or fallback, while an exact Z3 proof removes both checking and fallback on the valid edge. Direct variable equalities are collapsed into Z3-verified alias classes, so constraints such as `x == y` sample one field and copy it instead of relying on rejection. Acyclic arithmetic, bitwise, comparison, reduction, logical, conditional-select, concatenation, and constant-replication definition chains such as `x == y + 1; y == z + 1` are extracted from the versioned RPN program, topologically ordered, and emitted directly as MLIR; these definitions may read runtime captures, so `x == f(capture)` becomes generated MLIR instead of runtime search. Cyclic components remain on the checker/runtime path. Alias classes and definitions share one dependency plan: a uniquely defined class member becomes the representative, definition reads are canonicalized to representatives, and aliases are copied after their defining chains. Hard constraints are partitioned deterministically by shared random properties before table planning, with capture dependencies tracked per constraint; the conservative component masks are exposed with the analysis so distribution-sensitive clients can prove that unresolved variables do not cross ordering layers. Capture-free residual formulas and connected components with at most 4096 representation bits are completely enumerated when they have at most 16 solutions. Clients that require the complete joint distribution can request bounded global enumeration even when a structural proposal is already exact; if that global enumeration exceeds its bound, component enumeration still proceeds. Each component table is independently Z3-proven and retained even when another component exceeds the limits or depends on a runtime capture; the whole-formula proof composes retained tables with structural capture plans, while unresolved components continue through the generated checker and runtime fallback. When every component is covered, the Cartesian product may be exact even with far more than 16 aggregate solutions and can bypass checking. Every complete solution set becomes a sorted assignment table: power-of-two cardinalities use random low bits, while other cardinalities use generated 64-bit rejection sampling that threads additional object-local PCG draws only across rejection edges and commits the accepted state once. `solve before` global and component tables instead become topologically layered decision trees, with uniform sampling at each conditional node. For exact structural plans, lowering computes the transitive property dependency closure after validating that every solver step was materialized, and routes any later-layer source that determines an earlier-layer target to the ordered residual fallback. When Z3 proves that a structural proposal or complete assignment-table product implies the hard formula, generated code commits directly. If a definition or alias overwrites an independently constrained target domain, the generated checker and runtime fallback are retained. The encoder preserves implicit conversions structurally instead of turning converted constants into runtime captures. The build uses single-threaded polling mode so compiler-side Z3 remains WebAssembly-friendly, and the in-process shim serializes compiler entries because that configuration is intentionally non-thread-safe while MLIR may lower units concurrently; Z3 is never linked into `libobelisk_rt`. With `OBELISK_ENABLE_Z3=OFF`, conservative analysis returns unknown and emits the identical runtime fallback. |

Known-answer runtime tests pin the PCG sequence, state restoration, and bounded
draw behavior. Driver tests compare native and bytecode output at `-O0` and
`-O3` and across the 1800-2017 and 1800-2023 language modes.
