# Randomization support

This matrix separates the executable unconstrained random-number and stream
foundation from the remaining constrained-randomization work. A row is
“executable” only when it follows the same typed Simulation IR through native
and whole-design bytecode execution.

| Feature | Current boundary |
| --- | --- |
| Generator | Executable PCG-XSH-RR with explicit `{state, increment}` state and the existing `--seed=<u64>` option. The bounded draw uses rejection debiasing. |
| Process streams | Executable. Root processes split from the seeded context stream, and forked processes split the active parent stream in lexical spawn order. Bytecode tasks retain their stream while dequeued from the scheduler. |
| Object streams | Executable for the constrained-randomization slice. Every root class contains two hidden, inline, GC-invisible `i64` fields. Construction initializes them before `new`; class copy reseeds the copy; `randomize()` advances this object-local PCG state in native and bytecode execution. |
| `$urandom` | Executable with zero arguments and with the optional seed argument. |
| `$urandom_range` | Executable with one or two arguments, including reversed bounds, with an unbiased inclusive range. |
| `$random` | Executable with zero arguments. The optional seed form reseeds the active stream and writes the generated value back to the seed variable. |
| `$srandom` | Executable with one argument; it reseeds the active process stream without drawing a value. |
| Stream snapshot API | The runtime C ABI supports exact get/set of both PCG words and pure state-local stepping/bounded draws. Object `get_randstate` / `set_randstate` source methods are pending their string encoding. |
| Constraint blocks and `randomize()` | Executable for non-static, non-enum packed integral `rand` properties with at most 64 aggregate random bits. Total, side-effect-free hard expression constraints, one top-level soft expression preference, `inside` ranges, implication, conditional constraints, uniqueness, inheritance, package/design captures, and inline `with` constraints compile to pointer-free SSA. Fixed-width shifts are total, including oversized amounts. Division and modulo are accepted with a statically known nonzero divisor. Integral power accepts an unsigned exponent or a statically known nonnegative signed exponent. These operators participate in Z3 proofs and compile-time proposal definitions; the versioned pointer-free runtime program implements the same operations for residual fallback. The object-local PCG draw chooses the starting assignment. Generated code checks up to 64 cyclic candidates, then invokes the fallback with a deterministic attempt budget: the full domain through 20 aggregate bits and up to 2^20 candidates for wider domains. A soft preference is dropped only after a complete finite-domain search proves it unsatisfiable. Property writes occur only on the success edge, so failed solves commit nothing. Tagged-union domains, constraint function calls, dynamic-zero division, and signed dynamic or negative integral exponents remain unsupported. |
| `rand_mode` / `constraint_mode` | Pending the versioned randomization plan and dynamic mask layout. |
| `dist`, `solve before`, multiple or nested `soft` constraints | Pending weighted, priority, and solve-order planning. Unsupported forms are diagnosed before executable IR is produced. |
| `randc` | Pending; the intended executable boundary is packed integral widths up to 32 bits. |
| `pre_randomize` / `post_randomize` | Pending virtual-hook execution; user-defined hooks are diagnosed rather than silently skipped. |
| Compiler Z3 planning | A pinned Z3 4.13.4 static library is built from source for the compiler only. Residual programs are decoded into a temporary MLIR SMT bit-vector formula, then an in-process shim executes that formula through the Z3 API; no solver subprocess or SMT-LIB round trip is used. Z3 diagnoses constraints that are unsatisfiable for every runtime capture value and computes conservative per-property domains under a deterministic resource limit. Contiguous domains are folded without modulo bias into the generated tier-0 proposal: power-of-two cardinalities use random low bits, while arbitrary cardinalities use generated 64-bit rejection sampling and overflow-safe cyclic retry traversal. Direct inclusive unsigned capture bounds below 64 bits, such as `x <= limit` or `x >= limit`, become parameterized MLIR samplers: the capture is masked once, its runtime cardinality is sampled with unbiased 64-bit rejection, and an exact Z3 proof can remove both checking and fallback. Direct variable equalities are collapsed into Z3-verified alias classes, so constraints such as `x == y` sample one field and copy it instead of relying on rejection. Acyclic arithmetic, bitwise, comparison, reduction, logical, and conditional-select definition chains such as `x == y + 1; y == z + 1` are extracted from the versioned RPN program, topologically ordered, and emitted directly as MLIR; these definitions may read runtime captures, so `x == f(capture)` becomes generated MLIR instead of runtime search. Cyclic components remain on the checker/runtime path. Alias classes and definitions share one dependency plan: a uniquely defined class member becomes the representative, definition reads are canonicalized to representatives, and aliases are copied after their defining chains. Hard constraints are partitioned deterministically by shared random properties before table planning, with capture dependencies tracked per constraint. Small capture-free residual formulas and connected components up to 12 random bits are completely enumerated when they have at most 16 solutions. Each component table is independently Z3-proven and retained even when another component exceeds the limits or depends on a runtime capture; the whole-formula proof composes retained tables with structural capture plans, while unresolved components continue through the generated checker and runtime fallback. When every component is covered, the Cartesian product may be exact even with far more than 16 aggregate solutions and can bypass checking. Every complete solution set becomes a sorted assignment table: power-of-two cardinalities use random low bits, while other cardinalities use generated 64-bit rejection sampling that threads additional object-local PCG draws only across rejection edges and commits the accepted state once. When Z3 proves that a structural proposal or complete assignment-table product implies the hard formula, generated code commits directly. If a definition or alias overwrites an independently constrained target domain, the generated checker and runtime fallback are retained. The build uses single-threaded polling mode so compiler-side Z3 remains WebAssembly-friendly; Z3 is never linked into `libobelisk_rt`. With `OBELISK_ENABLE_Z3=OFF`, conservative analysis returns unknown and emits the identical runtime fallback. Strict, signed, 64-bit, expression-derived, and intersecting capture-domain plans remain pending. |

Known-answer runtime tests pin the PCG sequence, state restoration, and bounded
draw behavior. Driver tests compare native and bytecode output at `-O0` and
`-O3` and across the 1800-2017 and 1800-2023 language modes.
