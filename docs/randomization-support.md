# Randomization support

This matrix separates the executable unconstrained random-number and stream
foundation from the remaining constrained-randomization work. A row is
“executable” only when it follows the same typed Simulation IR through native
and whole-design bytecode execution.

The [Clause 18 audit](lrm-randomization-audit.json) records 113 feature checks
across all 57 numbered subsections of IEEE 1800-2023 Clause 18, with source
and MLIR regression evidence. Partial, missing, and review entries remain open;
the inventory is not a full conformance certification. Check its coverage
against a local licensed LRM with
`python3 scripts/audit-lrm-randomization.py --lrm build/lrm-2023.txt`.

Packed structs and untagged unions have the full integral random domain,
including unnamed encodings of nested enum members. Standalone enums and
arrays of enums retain enumerator membership. Packed tagged-union random
declarations are illegal under 18.4; legacy synthetic IR domain tests do not
make them supported source declarations.

Integral system functions `$signed`, `$unsigned`, `$clog2`, `$countones`,
`$countbits`, `$onehot`, and `$onehot0` participate in the bidirectional
bit-vector constraint relation without introducing user-function priority.
Bit counting uses balanced sums at the minimum count width in Z3; wide
results can also become proven definitions in generated code. Random
`$isunknown` inputs are two-state; mixed unknown-plane state remains open.
These paths execute in native and WASM runtime builds.

Runtime Z3 resolves ordinary integral residual solves with current state
captures, inactive bits, constraint modes and active semantic domains. After
proving the optimal enabled soft priorities, it samples each independent
constraint component uniformly. Sparse components use complete Z3-proven
projection tables; other components use Z3 Boolean bit blasting and exact
reduced decision-diagram counts. Counts and rejection-sampled ranks have
arbitrary precision, including full domains beyond 64 bits. Free assignment
bits are sampled independently; frozen state and auxiliary solver terms do
not multiply the counts. Exact counting can require exponential work for
complex Boolean relations.

The compiler opts in through `SMT_UNIFORM` in the versioned program header.
A nonzero work bound enables exact solving; zero still requests no solve.
Existing bounded C ABI clients retain their work limit and cyclic ordering;
`SMT_COMPLETION` clients can separately opt into complete cyclic discovery.
For packed integral aggregates of arbitrary width, ordered runtime residuals
count existential projections of each enabled solve-order layer, sample its
legal values uniformly, and cofactor the original relation before solving
later layers. This works with live captures, semantic domains, frozen properties,
constraint modes and optimal soft priorities without the old 2^20 traversal
limit. Version-2 records carry multiword ordering masks, and compiler
tables use arbitrary-width projection keys. Weighted and dynamic-foreach
residual paths retain their existing limits. This does not close the non-integral
or container gaps in the audit.

Both target runtimes statically link the pinned Z3 source, using the native
target libc++ ABI and Emscripten's JavaScript exception ABI respectively.
The browser host initializes static constructors and implements exception
unwinding and ownership without WebAssembly exception instructions. A build
check verifies libc++abi's metadata layout, and target staging includes Z3's
MIT license.

Resolved external constraint bodies use the ordinary Z3 and runtime plans;
undefined implicit prototypes are empty constraints, and missing explicit
extern bodies are diagnosed.

`disable soft` supports direct variables and fixed packed paths, declaration
priority, conditional and implication guards, and live constraint block modes.
Both Z3 planning and the generated/runtime checkers preserve the same rules.
`randcase` interprets its self-determined weights as unsigned and sums them at
the maximum operand precision, including modular overflow and zero-total cases.

Constraint execution includes IEEE 1800-2023 18.5.7.1 universal `foreach`
predicates over one-dimensional dynamic arrays and queues. The live container
size is sampled for each candidate, the declared iterator type is respected,
and an empty container contributes the identity value `true`. Multidimensional,
fixed-array, associative-array, and string forms remain explicit boundaries.
The current dynamic-`foreach` solver path accepts ordinary packed random
domains without `solve before`; finite semantic domains require a future
domain-index traversal. It checks a complete aggregate domain through 2^20
assignments and otherwise retains the global bounded-solver limit.

Recursive polymorphic object paths specialize only dynamic classes with
observable randomization behavior (rand state, effective constraints, or
non-builtin lifecycle hooks). Null and behaviorally inert concrete classes
share one no-op alternative. Behavior-bearing alternatives retain their
effective virtual `pre_randomize` and `post_randomize` hooks in the selected
whole-object-graph plan. For finite acyclic type graphs, runtime class identity
also joins distinct paths that reach the same object: corresponding packed
leaves are one solver variable, lifecycle hooks run once, and each dynamic
container field is randomized once. Recursive type cycles remain an explicit
boundary because a static path expansion cannot distinguish an ancestor alias
from an arbitrarily long chain of fresh objects; they require a runtime object
graph walk.

| --- | --- |
| Generator | Executable PCG-XSH-RR with explicit `{state, increment}` state and the existing `--seed=<u64>` option. The bounded draw uses rejection debiasing. |
| Process streams | Executable. Root processes split from the seeded context stream, and forked processes split the active parent stream in lexical spawn order. Bytecode tasks retain their stream while dequeued from the scheduler. |
| Object streams | Executable for the constrained-randomization slice. Every root class contains two hidden, inline, GC-invisible `i64` fields. Construction initializes them before `new`; class copy reseeds the copy; `randomize()` advances this object-local PCG state in native and bytecode execution. |
| `$urandom` | Executable with zero arguments and with the optional seed argument. |
| `$urandom_range` | Executable with one or two arguments, including reversed bounds, with an unbiased inclusive range. |
| `$random` | Executable with zero arguments. The optional seed form reseeds the active stream and writes the generated value back to the seed variable. |
| `$srandom` | Executable with one argument; it reseeds the active process stream without drawing a value. |
| Stream snapshot API | The runtime C ABI supports exact get/set of both PCG words and pure state-local stepping/bounded draws. Object and `process` `get_randstate` / `set_randstate` source methods preserve exact snapshots; object and process `srandom` use the same canonical seed mapping. |
| Constraint blocks and `randomize()` | Executable for packed integral, enum, packed aggregate, and frontend-admitted packed tagged-union `rand` properties and for `randc` properties up to the boundary below, including static properties in ordinary `randomize()`. Static values use class-wide design storage and static `randc` properties use one shared persistent cycle advanced by calls through any instance. An explicit object property argument list temporarily makes exactly those properties random for the call: unlisted instance `rand`/`randc` properties become state, listed non-rand properties become ordinary random variables, listed `randc` properties retain cyclic behavior, and the persistent `rand_mode` mask is not changed or consulted for that temporary selection. Explicitly selected static properties use the same class-wide storage and cycle. Enum enumerators and canonical tagged-union arm encodings form exact semantic domains rather than exposing unused packed encodings; packed arrays compose enum domains, while packed structs and untagged unions admit their complete integral representation. A base- or interface-class-typed handle is specialized at compile time for every compatible concrete class and selects the most-derived plan with generated in-process type tests; the receiver is evaluated once, and a null or otherwise unmatched handle returns zero without touching object state. Active, non-null `rand` object handles are traversed recursively: descendant variables, constraint blocks, and descendant-local state captures participate in one solve, with every ancestor `rand_mode`, null state, and descendant `constraint_mode` applied along the exact object path. Dynamic arrays and queues whose class-handle element type has no compatible concrete class in the compilation follow the exact zero-object LRM case: unconstrained size and null elements are retained without allocation, writes, or random draws; constrained size still uses ordinary resize semantics and initializes any growth to null. `randomize(null)` uses the same dynamic plan selection as `randomize()`, invokes `pre_randomize`, checks the current property values against the live constraint-mode mask, and invokes `post_randomize` only on success; it performs no random draws, property writes, or hidden-state changes. Total, side-effect-free hard expression constraints, up to 64 soft expression preferences including implication- and conditional-guarded preferences, `inside` ranges, implication, conditional constraints, uniqueness, inheritance, package/design captures, inline `with` constraints, and side-effect-free user constraint functions compile to pointer-free SSA. Packed concatenation and known-positive constant replication are preserved in compile-time definitions and in residual programs; replication uses a fixed-width geometric placement multiplier rather than expanding one runtime operation per repetition. Admitted functions have packed input or const-ref arguments and define their result with one expression return or blocking return-variable assignment; nested calls are expanded recursively and virtual calls on the randomized receiver resolve against the selected concrete-class plan. Rand packed value paths passed as function arguments remain solver variables and create bit-range-precise LRM implicit solve-order edges, while rand properties read only inside the function body are captured at their pre-solve values. Dynamic candidate-dependent packed selections in those paths remain unsupported. Each constraint tree is separated into its hard projection and guarded soft predicates. Later class declarations, derived-class constraints, and inline constraints receive progressively higher soft priority. For capture-free formulas, Z3 selects the lexicographically best satisfiable priority set and proves exact structural domains, definitions, or tables for generated code. Capture-dependent or dynamically disabled preferences remain on the complete residual traversal, which selects the best enabled priority set before dropping lower-priority preferences. Fixed-width shifts are total, including oversized amounts. Division and modulo are accepted with a statically known nonzero divisor. Integral power accepts an unsigned exponent or a statically known nonnegative signed exponent. These operators participate in Z3 proofs and compile-time proposal definitions; the versioned pointer-free runtime program implements the same operations for residual fallback. The object-local PCG draw chooses the starting assignment. Generated code checks up to 64 cyclic semantic candidates, then invokes the fallback with a deterministic attempt budget of up to 2^20 semantic assignments. Property and hidden `randc` cycle-state writes occur only on the success edge, so failed solves commit nothing. Constraint functions with procedural control flow or an explicit receiver other than the randomized object, system functions beyond the integral bitstream set, mixed unknown-plane captures, dynamic-zero division, and signed dynamic or negative integral exponents remain unsupported. |
| `std::randomize` | Executable for up to 64 distinct direct variable identifiers naming automatic, formal, static, package, or design-scope values with fixed packed integral, enum, packed aggregate, or frontend-admitted packed tagged-union types. The listed variables are the random set; every other referenced value is captured as state at the call. Inline total expression constraints, soft priorities, semantic domains, and direct-variable `solve before` use the same frozen solver plan as object randomization. Successful solves commit every listed variable and advance the active process or initialization stream; failed solves commit no variable changes. The zero-argument form checks its inline constraints without changing variables or advancing the stream. Dynamic containers, class handles, constraint-function calls, and selected variable paths remain explicit diagnostics. |
| `rand_mode` / `constraint_mode` | Class-wide and property-specific `rand_mode` setters and queries are executable through zero-initialized disabled-property state. Instance properties use the object's mask; each static random property has one class-wide mode word shared by every instance. Both `C::property.rand_mode(...)` and object-qualified static-property forms address that shared word, and class-wide calls use dynamic-class dispatch to update the exact inherited static set. Disabled properties retain their current values, participate in constraints as state variables, consume no search-domain bits, and are not written on success. Class-wide `constraint_mode(on_off)` and named-block setters and queries are executable through a separate disabled-block mask for up to 64 effective inherited constraint blocks. Overrides retain the base block's stable bit; `constraint ... extends` declarations append under that same bit. The all-enabled constraint path retains its Z3-planned sampler. Any disabled block bypasses plan-specific narrowing and extra draws, uses the generated live-mask checker, and passes both property and constraint masks to the deterministic residual solver. Inline constraints remain unmaskable. If all random properties are disabled, `randomize()` checks current values against the enabled hard constraints without advancing the object stream or writing properties. |
| `solve before` | Direct rand-property DAGs are executable. The compiler validates self edges and cycles, reorients pure alias classes toward the earliest ordered member, and emits conditional sampling as MLIR when Z3 proves complete global/component tables or exact structural plans whose transitive dependencies follow the order. Residual programs retain constraint-block-aware ordering edges. For packed integral aggregates of arbitrary width, target Z3 resolves the optimal enabled soft priorities, then counts existential projections of each active topological layer and samples its distinct legal values uniformly. Compiler and runtime DAG plans defer partially ordered fields to their latest legal layer and include unordered fields in the final joint group. Cofactoring the original relation preserves constraints on later fields. Live captures, semantic domains, partial rand modes and constraint modes use the same exact policy; disabling an ordering block removes its edges. Remaining unordered fields use their conditional joint distribution. Version-2 metadata carries multiword before/after masks and validates padding, block identities and declaration cycles before applying modes. Real ordering and general selected paths remain incomplete. Without runtime Z3, narrow ordered residual traversal retains the 2^20 semantic-assignment limit and wide ordered residuals are diagnosed. |
| `dist` | Executable for a direct packed integral or enum `rand` property with compile-time two-state singleton/range endpoints, including unary signed constants. Both `:=` per-value weights and `:/` per-range weights, including a default weight, are normalized exactly with checked 64-bit integer arithmetic. State-dependent packed integral weights are evaluated once at driver entry. Generated MLIR performs unbiased weighted range selection for ordinary packed domains. Finite semantic domains use compiler-counted legal values and the exact residual path, so sparse enum encodings do not distort `:/` normalization; this path currently requires at most 2^20 aggregate semantic assignments. The same normalized per-value table is serialized for constraint/property-mode fallback. The fallback attaches mass once to each distinct tuple of distributed target values, so unrelated companion-solution multiplicity cannot skew the declared distribution. Signed target domains use sign-bit-biased coordinates. Weights are interpreted as unsigned at their self-determined width. Zero total weight or arithmetic overflow currently makes `randomize()` fail. Range mass after other constraints exclude values remains an open conformance item. Soft `dist`, `dist` combined with `solve before`, `dist` on `randc`, multiple active distributions for one property, candidate-dependent weights, dynamic endpoints, and normalization or range mass that exceeds 64 bits are diagnosed explicitly. |
| `randc` | Executable for packed semantic domains containing at most 2^32 values within a packed representation no wider than 32 bits. Sparse enum and tagged-domain values are addressed by dense semantic indices, so unused encodings are skipped without bias. Each instance property has hidden GC-invisible key and position fields; a static property instead has one class-wide pair in design storage. A deterministic keyed four-round Feistel permutation produces every semantic index exactly once per cycle in O(1) state; wrapping explicitly draws a new key from the object-local PCG stream. An enabled `randc` value advances before ordinary `rand` solving. A single-property plan skips rejected cyclic candidates and restarts an exhausted cycle; general joint cycle-domain changes remain an open conformance item. Its field, key, and position are committed together only after a successful solve. A disabled property retains both its value and cycle state. The pure Simulation op lowers to a direct runtime API call in native code and to the corresponding intrinsic in whole-design bytecode; runtime GoogleTests exhaustively prove bijectivity through width 16 and exercise the bytecode intrinsic. Wider representations or semantic domains larger than 2^32 are diagnosed. |
| `pre_randomize` / `post_randomize` | Executable with virtual override semantics through the same compile-time-specialized dynamic-class plan as `randomize()`. The effective `pre_randomize` runs after receiver selection but before mode, constraint, property, or stream state is read. The effective `post_randomize` runs after all successful property and `randc` state commits, including a successful current-value check when every property is disabled, and is skipped on failure and null receivers. Inherited hooks receive a receiver cast to their declaring class. Package and design captures used by either hook are propagated through the generated call plan. |
| Compiler Z3 planning | A pinned Z3 4.13.4 static library is built from source for compiler analysis. Residual programs are decoded into a temporary MLIR SMT bit-vector formula, then an in-process shim executes that formula through the Z3 API; no solver subprocess or SMT-LIB round trip is used. Z3 diagnoses constraints that are unsatisfiable for every runtime capture value and computes conservative per-property domains under a deterministic resource limit. Contiguous domains up to 64 bits are folded without modulo bias into the generated tier-0 proposal: power-of-two cardinalities use random low bits, while arbitrary cardinalities use generated 64-bit rejection sampling and overflow-safe cyclic retry traversal. Wider variables skip width-linear min/max discovery and instead use bounded solution enumeration when sparse. Direct signed and unsigned capture bounds up to 64 bits, including side-effect-free capture expressions evaluated once at driver entry, such as `x <= limit`, `x >= limit`, or their strict forms, become parameterized MLIR samplers: captures are masked once, signed endpoints are mapped to sign-bit-biased unsigned coordinates, strict endpoints are normalized with overflow guards, compatible lower and upper bounds and compile-time envelopes are intersected, and the runtime cardinality is sampled with unbiased 64-bit rejection. A zero cardinality represents the full 2^64-element domain and selects the original random draw while generated modulo operations use a nonzero safe divisor. An empty runtime intersection fails before modulo or fallback, while an exact Z3 proof removes both checking and fallback on the valid edge. Direct variable equalities are collapsed into Z3-verified alias classes, so constraints such as `x == y` sample one field and copy it instead of relying on rejection. Acyclic arithmetic, bitwise, comparison, reduction, logical, conditional-select, concatenation, and constant-replication definition chains such as `x == y + 1; y == z + 1` are extracted from the versioned RPN program, topologically ordered, and emitted directly as MLIR; these definitions may read runtime captures, so `x == f(capture)` becomes generated MLIR instead of runtime search. Cyclic components remain on the checker/runtime path. Alias classes and definitions share one dependency plan: a uniquely defined class member becomes the representative, definition reads are canonicalized to representatives, and aliases are copied after their defining chains. Hard constraints are partitioned deterministically by shared random properties before table planning, with capture dependencies tracked per constraint; the conservative component masks are exposed with the analysis so distribution-sensitive clients can prove that unresolved variables do not cross ordering layers. Capture-free residual formulas and connected components with at most 4096 representation bits are completely enumerated when they have at most 16 solutions. Clients that require the complete joint distribution can request bounded global enumeration even when a structural proposal is already exact; if that global enumeration exceeds its bound, component enumeration still proceeds. Each component table is independently Z3-proven and retained even when another component exceeds the limits or depends on a runtime capture; the whole-formula proof composes retained tables with structural capture plans, while unresolved components continue through the generated checker and runtime fallback. When every component is covered, the Cartesian product may be exact even with far more than 16 aggregate solutions and can bypass checking. Every complete solution set becomes a sorted assignment table: power-of-two cardinalities use random low bits, while other cardinalities use generated 64-bit rejection sampling that threads additional object-local PCG draws only across rejection edges and commits the accepted state once. `solve before` global and component tables instead become topologically layered decision trees, with uniform sampling at each conditional node. For exact structural plans, lowering computes the transitive property dependency closure after validating that every solver step was materialized, and routes any later-layer source that determines an earlier-layer target to the ordered residual fallback. When Z3 proves that a structural proposal or complete assignment-table product implies the hard formula, generated code commits directly. If a definition or alias overwrites an independently constrained target domain, the generated checker and runtime fallback are retained. The encoder preserves implicit conversions structurally instead of turning converted constants into runtime captures. Native compiler workers use Z3's thread-safe build with isolated thread-local contexts, while the non-pthread WebAssembly compiler retains single-threaded polling mode and a process gate. Target-specific static Z3 libraries are merged into the native and WASM runtime archives when `OBELISK_ENABLE_RUNTIME_Z3=ON` (the default with compiler Z3 enabled). With `OBELISK_ENABLE_Z3=OFF`, conservative analysis returns unknown and uses runtime Z3 when enabled independently, or bounded runtime traversal when both solver options are off. |

Known-answer runtime tests pin the PCG sequence, state restoration, and bounded
draw behavior. Driver tests compare native and bytecode output at `-O0` and
`-O3` and across the 1800-2017 and 1800-2023 language modes.
